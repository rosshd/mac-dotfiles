# Point of view

Earn a clear recommendation against the user's actual project and constraints.

## Workflow

1. Define the decision, alternatives, reversibility, and success criteria.
2. Read the project's code, strategy, prior decisions, and operational constraints that bear on the choice.
3. Verify current external claims with primary sources when they affect the recommendation.
4. Compare options on the few criteria that change the decision rather than producing a generic feature table.
5. State the verdict, confidence, strongest reason, important tradeoffs, and conditions that would change the answer.
6. Recommend the smallest sensible next step without implementing it unless requested.

Form the recommendation locally and independently.

Consult subagents or outside models only when the user explicitly requests an oracle, panel, reconciliation, or independent peer review.

Do not disguise missing evidence as confidence.
